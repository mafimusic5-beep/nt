# Региональная политика на VPN-серверах

Ветка: `feature/server-regional-policy`, исходная версия: `f10bd5c`.

## Что меняется

Выбор «Международная» / «Российская Федерация» сохраняется. Android **не скачивает
базы ограничений** ни при выборе политики, ни при подключении. Перед подключением
в региональном режиме выполняется небольшой подписанный запрос проверки сервера.
Он не содержит списков; сетевой обмен имеет общий таймаут 8 секунд после DNS-разрешения.
Каждое последующее соединение также авторизуется отдельно.

| Выбранная политика | Авторизация шлюза | Серверный обработчик |
| --- | --- | --- |
| Международная | Прежний протокол v1 | Существующий Xray, `127.0.0.1:<порт устройства>` |
| Российская Федерация | v2: подписаны политика и действие | Отдельный Xray, `127.0.0.2:<тот же порт>` |

UUID, Reality/Vision и ограничения скорости сохраняются. Выбор режима не меняет
конфигурацию общего Xray и не вызывает его перезапуск. Существующая процедура
добавления/отзыва устройства по-прежнему перезапускает основной Xray; в неё добавлена
синхронизация его отдельных учётных записей с региональным процессом.
Одинаковые номера портов сохраняют общий серверный лимит скорости для обоих режимов.
Подключение к обычному импортированному профилю без защищённого шлюза в региональном
режиме запрещено.
Для него требуется режим VPN: старый proxy-only сервис без защищённого шлюза
не запускается с выбранной региональной политикой.

Старые клиенты сохраняют v1-подключение и свою прежнюю локальную политику. Новый
клиент не принимает ответ старого сервера как подтверждение серверной фильтрации.
Выбор режима добровольный; это не определение страны пользователя по IP.

## Источник и границы фильтрации

Сохранены источники прежней реализации: `ru-blocked-all`, `ru-blocked`,
`ru-blocked-community`, `re-filter` из
[runetfreedom/russia-v2ray-rules-dat](https://github.com/runetfreedom/russia-v2ray-rules-dat).
Это **списки запрещённых доменов/IP**, а не режим «разрешены только сайты из белого
списка». Репозиторий сообщества не является официальным реестром Роскомнадзора;
полнота юридических ограничений этим изменением не гарантируется.

Фильтрация доменов/IP не равнозначна анализу содержимого HTTPS, отдельных URL или
вложенных туннелей. Шифрование имени сервера, внешние прокси и общие IP требуют
отдельной оценки. Совпадение IP общего хостинга может ограничить и другие сайты.
SMTP/private-IP и прежнее ограничение UDP/443 сохранены. DNS-транспорт на порту 53
остаётся доступен после проверки доменов и private-IP, как в предыдущей политике.
Правила и DNS-стратегия меняются только в отдельном региональном процессе.
Формат правил: [документация Xray](https://xtls.github.io/en/config/routing.html).

## Установка — отдельно от коммита

**Коммит/публикация этой ветки не устанавливает фильтрацию на работающие VPS.**
Сначала проверить на тестовом узле. Не направлять новый клиент в региональном режиме
на неподготовленный сервер: он откажется подключаться, а не обойдёт ограничения.

1. Обновить контрольный API `orchestrator` из этой ветки: он проверяет подпись v2.
   Не менять ключи устройств, базу активаций или `DEVICE_GATE_API_KEY`.
2. Обновить пул `emery vpn orchestrator/src` из этой ветки. SSH-транспорт автоматически
   вызывает установленный `/opt/emery/regional-policy/regional_policy.py` при выдаче
   и отзыве доступа, под прежней блокировкой конфигурации. Скрипт должен принадлежать
   root и быть недоступным для записи группе/остальным.
3. Если используется собственный `XRAY_CREDENTIAL_SCRIPT`, добавить в него вызов
   `python3 /opt/emery/regional-policy/regional_policy.py sync-credentials --source-config <config>`
   **после** успешного изменения учётных записей. Флаг `--credential-lock-held` допустим
   только внутри уже удерживаемого `.emery-xray-credentials.lock`. Без синхронизации
   новые назначения не будут готовы в региональном режиме; поле назначения в записи
   готовности защищает от использования старого владельца повторно выданного порта.
4. На каждом VPN-узле обновить `deploy/device-gate/emery_device_gate.py` в существующем
   `/opt/emery/device-gate/`. Сохранить прежние TLS-сертификат, pin, ключ API и настройки
   шлюза. Перезапуск шлюза кратковременно прервёт его текущие соединения — нужен
   согласованный момент обслуживания.
5. На узле из каталога `emery vpn orchestrator` выполнить:

   ```bash
   sudo bash deploy/regional-policy/install.sh
   ```

   Скрипт устанавливает отдельные файлы и сохраняет предыдущие версии. Основной Xray
   не перезапускается и его конфигурация не переписывается. Существующие права `/etc/emery`
   не меняются. Требуются Linux/systemd, Python 3.10+, `/usr/local/bin/xray` и свободная
   память для второго Xray и проверки больших списков. Проверить запас RAM/диска на
   реальном узле; этот код не увеличивает VPS автоматически.
6. Проверить `/etc/emery/regional-policy.env`: путь должен совпасть с `XRAY_CONFIG_PATH`
   пула. Исходная конфигурация должна быть root-owned, без записи группе/остальным;
   первый outbound — именованный `freedom`. При нестандартном пути бинарника также
   изменить `ExecStart` в отдельном unit через systemd override.
7. Первоначальная подготовка выполняется **на сервере**, до раздачи новой сборки:

   ```bash
   sudo systemctl start emery-regional-policy-update.service
   sudo systemctl status emery-regional-xray.service --no-pager
   sudo systemctl enable --now emery-regional-policy-update.timer
   sudo systemctl restart emery-device-gate.service
   ```

8. Выполнить проверочный сценарий ниже, затем собрать/раздать Android из этой ветки.

## Обновление и отказоустойчивость

Таймер загружает базы на VPN-узел каждые шесть часов. Во время загрузки текущий
снимок продолжает работать; блокировка выдачи устройств на время скачивания не
удерживается. Два файла проверяются по SHA-256 источника, затем `xray run -test`
проверяет конфигурацию и наличие всех обязательных групп. Ошибка загрузки или
проверки не заменяет рабочую базу.

После проверки атомарно переключается снимок и перезапускается **только**
`emery-regional-xray`. Региональные соединения при этом могут переподключиться;
это не бесшовная горячая перезагрузка. Международный процесс не перезапускается.
После проверки слушающих портов создаётся небольшая root-owned запись `ready.json`.
Шлюз проверяет её возраст, порт и назначение устройства; сами базы он не читает.

Снимок без успешного обновления более 48 часов не принимается: новые региональные
соединения отклоняются, длительные соединения ограничены сроком снимка. Это выбранный
технический срок, а не нормативный интервал. Нет fallback на международный режим.
Если изменились учётные записи, неудачная синхронизация останавливает региональный
процесс, чтобы не вернуть отозванные UUID. Откат базы разрешён только при совпадении
хэша исходной конфигурации устройств.

Хранятся текущий снимок и один предыдущий. Более старые автоматически созданные
каталоги `snapshot-*` удаляются; чужие каталоги не затрагиваются. Снимки содержат
серверные ключи/учётные записи и доступны только root и отдельному сервисному
пользователю. Не публиковать их или основную конфигурацию в логах/репозитории.

## Проверка перед выпуском

```bash
cd 'emery vpn orchestrator'
PYTHONDONTWRITEBYTECODE=1 python -m pytest -q tests
cd ../orchestrator
PYTHONDONTWRITEBYTECODE=1 python -m pytest -q tests
cd ..
bash gradlew :app:testPlaystoreDebugUnitTest :app:assemblePlaystoreDebug --no-daemon
```

На тестовом узле и телефоне:

- Первый выбор региональной политики без ранее скачанных клиентских `.dat`: нет
  HTTP-запросов Android к источнику баз; выбор сохраняется без сети.
- Региональный режим: обычный сайт доступен, контрольные домен и IP из установленной
  базы блокируются. Проверить DNS, IPv4, захват IPv6, Wi-Fi и мобильную сеть.
- Международный режим и Reality/Vision работают как до изменений.
- Остановить только региональный процесс: приложение получает отказ; обычный режим
  продолжает работать. Не должно быть сообщения об успешной защите с обходом политики.
- Отозвать устройство, затем переиспользовать порт: старое назначение/подпись не
  получает доступ. Проверить личный/семейный тарифы и лимит скорости в обоих режимах.
- Ошибка SHA, отсутствие обязательной группы, недоступность источника: рабочая база
  остаётся до срока годности; отсутствие подтверждённой базы не даёт обхода.
- Переключить режим несколько раз: не должно быть запросов на скачивание списков
  или перезапусков общего Xray, вызванных **самим выбором политики**.

Возврат: оставить международный режим, вернуть прежний APK при необходимости,
остановить региональный таймер и сервис. Не перенаправлять региональные запросы
на `127.0.0.1` для сокрытия ошибки. Откат production/main — отдельная операция.
