## Протокол добавления/исправления функции
- Перед правкой: перечислить ID затронутых функций и точные зависимости.
- При обнаружении неучтённого поведения: добавить ID и инвариант **до** изменения кода.
- Вместе с патчем: указать путь теста, запуск и результат. Если теста нет, явно написать «нет покрытия».
- Перед релизом: прогнать тесты всех затронутых ID и связанных пользовательских путей. Критические device-тесты требуют реального устройства.
- Если меняется UX/контракт: сначала согласование с владельцем проекта. Не выдавать удаление за исправление.
- После изменения: обновить эту таблицу и историю проверок в PR; не заявлять «0 регрессий» без подтверждения.

## Текущие известные ограничения
- Наличие успешной Android-сборки в CI не подтверждает соединение на реальном телефоне.
- В workflow activation-key-tests обнаружены 2 падающих теста жизненного цикла ключей. До разбора нельзя считать весь CI зелёным.
- Этот реестр не является исчерпывающей инвентаризацией; требуется поэтапно подтвердить каждую строку по исходникам.
