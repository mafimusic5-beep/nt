# Skryon orchestrator

Минимальный сервер для активации кодов Skryon.

Состав:
- SQLite база.
- API для проверки кода.
- Таблица кодов активации.
- Двухфазная бронь места в общем пуле и персональная VLESS-ссылка устройства.

Запуск API:
python -m uvicorn api:app --host 0.0.0.0 --port 8080

Синхронизация конфигов:
- `POST /api/config/sync` держит запрос до 25 секунд и сразу возвращает новую ревизию после `/addconfig`, `/useconfig` или `/delconfig`.
- Запрос разрешён только коду, уже привязанному к указанному `deviceId` через `/api/activate`.
- Бот и API должны использовать один и тот же `DATABASE_PATH`.
- Для старых APK бот зеркалит `/addconfig` и `/delconfig` в общий Emery-пул. Отдельный ключ не нужен: бот использует `ADMIN_API_KEY` и `BACKEND_BASE_URL` из окружения или из существующего Emery `.env`. Нестандартный путь можно передать через `EMERY_ENV_FILE`.
- После запуска бот автоматически публикует уже сохранённые конфиги в старом пуле. Команда `/syncconfigs` остаётся для ручной повторной проверки.
- Emery backend сохраняет старые контракты списка/pool и `regions/revision`, поэтому версии с обновлением при открытии, 30-секундным polling или long-poll получают изменения без смены APK.
- `MIN_SUPPORTED_APP_VERSION_CODE` задаёт минимальный переданный `versionCode` (для этой версии — `716`), а `APP_UPDATE_MESSAGE` — текст для устаревших клиентов. Клиенты без поля версии продолжают работать через legacy-контракты. APK без каких-либо запросов к backend получить этот текст не может; таких пользователей нужно уведомлять через канал распространения APK.
- При `POOL_BRIDGE_ENABLED=true` регистрация сначала резервирует реальный слот в
  Emery backend. В bridge уходят только HMAC-псевдонимы; code/device ID не
  передаются. HTTP 409 от пула откатывает регистрацию устройства.
- После локального commit вызывается `confirm`; незавершённые брони удаляет
  maintenance backend. Конфиг из общей таблицы `servers` используется только
  как legacy fallback, когда bridge явно отключён.

Реальные токены и секреты не храним в репозитории. Их нужно задавать локально через переменные окружения.
